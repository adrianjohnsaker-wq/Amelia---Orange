# Warp access: parity reversal and ordered-input experiment

## Question and standing

Can an explicitly engineered access route through Amelia's 3/6 circuit retain useful input information and produce an advantage during recovery from a parity reversal, relative to an occupancy-matched 2/7 loop and strong direct-feedback comparators? This is a prospective, synthetic challenge on copies of the eight previously available Oracle-origin lineages. They had separate origins but subsequently shared world input. Outcomes are not independent live-world ingress and cannot establish retrocausality, a mind, or autonomous self-improvement.

The exploratory access probes preceded this registration. Their full artifacts are recorded by hash in registration.json. In the existing implementation 3 has exits to 6 and 3, and 6 has an exit to 3. Native 2 and 7 have additional exits; the 2/7 comparator is an explicitly adapted, locally isomorphic loop, not an unmodified native graph. Assertions that the 3/6 topology is inherently non-Euclidean, noncommutative, or more capable are hypotheses, not design premises.

## Access intervention

A controller intercepts proposal-gate competition, adds a bounded symmetric bias, and uses actual Oracle stepping, House learning, process memory, and phase dynamics. It encodes each observed input bit by placing one dwell at the seventh or fourteenth proposal visit within a 27-transition block; the remaining 26 transitions alternate outward and return. The controller guarantees 1/27 = 3.7037% dwell and 13 transitions in each direction in each block for *both* routes. Maximum absolute added differential bias is 2, and governor hard-violation counts must remain unchanged. Every history round encodes the same public event and diagnostic feedback bits separately, costing 54 real gate transitions. The procedure deliberately writes an input bit into passage; the controller and its state are external experimental machinery, not spontaneous discovery. Normalized matched and Warp paths must be identical. Real and independently yoked feedback use the same encoder and path quotas.

## Challenges and exposure

For each origin and task family, the experiment uses 8 paired training and 8 paired test seeds; each seed produces both complementary initial parities. Test seeds are drawn only after this registration and analysis code are committed. Each episode has 16 rounds, switches after 3–5 and 10–11 rounds (zero-based switch times 3/4/5 and 10/11), and a noisy feedback bit equal to the current correct action with 25% error. Switch windows are at least five rounds apart. Both routes and all baselines receive exactly the same public event bit and diagnostic bit, and do not receive switch flags, true labels, or hidden parity during prediction. Training labels are used for the supervised readouts. Their step position is known, but the realized switch times are not. Evaluation windows are identified using the hidden schedule only after predictions are made.

Primary family `parity`: event bits are distractors and the correct action flips at each switch. Secondary, exploratory family `ordered`: public A toggles the first bit of a two-bit register, public B swaps the two bits; the target is parity XOR first register bit. A and B do not commute, a property of these specified operations, not evidence that the Warp circuit is non-Abelian. This task intentionally plants the relevant signals and uses no new world stream.

Each route separately selects from House-only, process-memory-plus-phase, combined, and quadratic-combined standardized nearest-centroid readouts using training pairs 0–3 for fit and training pairs 4–7 for validation; ties prefer the earlier view. The selected classifier is refitted on all training pairs. No test result chooses a view. The identical trained real-feedback classifier is also applied to each route's yoked-feedback states. A second House-only classifier, trained to decode the current diagnostic bit, measures usable information in the state as an ancillary diagnostic. Matched control receives the identical selection process and computational opportunity. All readouts are external supervised classifiers, not newly trained Oracle weights.

Comparators predict after receiving each round's current feedback: a constant strategy chosen on training labels; the current noisy cue; last-four parity-normalized feedback; and an adaptive ordered full-history Bayesian filter. The filter learns schedule frequencies and feedback noise on training episodes with Laplace smoothing; it knows the six allowed switch schedules and event transformation but not the realized test schedule, switch times, labels, or parity. The learned switch prior makes it a strong task-informed comparator, not a claim of universal real-world optimality. For the ordered family it updates the register from observed A/B events. No baseline is artificially held inert or presumed toxic.

## Outcome, inference, and validity

The single primary endpoint is accuracy pooled over the first five rounds after each switch in the parity task, equivalently correct actions per five. Each of 8 origins has 16 held-out episodes, 32 switch windows and 160 primary decisions; observations within an origin are not independent. Determine three pre-specified paired contrasts: Warp-real minus matched-real, Warp-real minus Warp-yoked, and Warp-real minus the adaptive full-history filter. For each contrast, compute the mean of the eight origin differences and an exact one-sided sign-flip test on those eight differences against zero; Holm-adjust the three p-values. Register `REGISTERED_ENGINEERED_WARP_ACCESS_ADVANTAGE` only if *all three* mean differences are at least 0.05 accuracy (0.25 correct decisions per five) and all Holm p-values are at most 0.05. The p-values test zero, not the 0.05 threshold. Otherwise register `NO_REGISTERED_WARP_ACCESS_ADVANTAGE`. Shared subsequent inputs and eight reused founders limit the strength of population inference.

Report the first post-switch round separately, fixed and current-cue baselines, all three individual comparisons and per-origin results regardless of overall classification, and the same descriptive results for the ordered task. Inspect House feedback decoding and real/yoked House differences without changing the primary rule. Any future search based on these outcomes requires a new registration and fresh test data.

Each of eight histories is independently generated twice and compared at 1e-12 numerical tolerance, and an independent Python program regenerates tasks and verifies all raw paths, quotas, feature dimensions and hashes. The fast adapter shim is compared against the original adapter on all eight origins and both routes, plus a 1,080-transition run per route. Probe, fixture, registration, source, run seed, raw histories, audit and outcomes are retained. Script or source changes after sealing invalidate this registration and require a new one. If quota, telemetry, matching, replay, governor, or audit checks fail, no outcome is classified until the cause is corrected under a new registration.
