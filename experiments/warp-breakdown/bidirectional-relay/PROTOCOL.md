# Amelia bidirectional syzygy relay: repeated-reversal test

## Research question

Can a feedback-writing channel into Amelia's 3/6 House source make her actual gate-selected strategy recover more quickly after repeated regime reversals, and is that acceleration specific to 3/6 rather than equally available to the matched 2/7 circuit, a generic House relay, or a direct learner? This is an engineered extension on copies of the pinned Oracle, not a claim that such a connection exists in the native Numogram. The prior post-hoc reversal suggested that remote reading could remain disconnected from updates; it did not establish that the difference in outcomes was caused solely by that disconnection.

The prior 15.80 transitions was a restricted mean time to choose the old-regime preferred action twice. It was **not** observed time to return to Zones 3/6. Nor was the previously observed 85.94% shown to be a performance ceiling. We retain those distinctions.

## Design and common resources

Reuse the eight available Oracle-origin checkpoints, later exposed to shared inputs. For each origin generate four paired seeds and both complementary initial regimes, giving eight episodes per origin and 64 episodes overall. Two full-graph preparations start from the same prepared historical state: native Warp 3/6 and the previously adapted 2/7 graph (its graph is restored on a Zone-5 death/reset). Each route receives 24 natural training decisions, each taking four Oracle gate transitions; two grid challenges are scored under the starting regime, and chosen-strategy feedback alone updates the selected local House source by the pre-existing rule.

Copy the resulting route-specific state to all comparison arms. Displace the copies to every eligible shock zone in {1,4,8} that differs from both trained route origins. The same shock zones, challenge seeds and regime schedule apply across the arms. The boundary changes only location; hash assertions verify that all other fields and the retained House vector match the host at this boundary. Arms remain continuous after displacement rather than being reset between reversals.

At displacement, invert regime 1↔3; invert again after each of two further intervals. Segment lengths are independently seeded integers in {10,11,12,13,14}, with three reversal segments per branch. Thus every segment contributes lags 1–10. The regime label, future schedule and counterfactual scores are hidden from the controller. The previously used LIGHT and HEAVY search strategies are evaluated on the same two grids in each round. Every arm receives its chosen action's score R∈{0,1,2} *after every post-displacement decision*, including decision 1; no feedback is withheld. A higher score means more grids solved at exact optimal cost within the computational budget.

The gate-selected action is the parity of the last branching gate's ordered target rank within a fixed four-transition decision. Each arm consumes four scored gate events per decision. Zero channel access is provided by the natural gate arm. A phase-focused relay sends one scalar per gate evaluation; it applies the same ±0.08-radian phase pulse as the previous sealed test and uses the same gain 0.5 and House-derived parity signal. A generic relay sends the earlier whole-House scalar with the same gain. These nonlocal signals and extra House operations are counted separately from gate transitions; the focus pair consists of native 3/6 for Warp and the matched 2/7 loop for control.

## Post-displacement comparison arms, on both routes

1. **Natural:** no added relay; selected-source feedback update only.
2. **Generic:** whole-House scalar to gate; selected-source feedback update only.
3. **Remote read-only:** focus-pair scalar to gate, selected-source feedback update only. Local House learning remains active; the focus source can be updated if selected through the ordinary graph. Read-only describes the *remote channel*, not a permanently frozen House.
4. **Bidirectional:** the same focus read plus a write to the pair's open branching sources after the ordinary selected-source update. For ordered options j, `V[j] = clip(-1,1, 0.75*V[j] + (R-1)*(+1 if j%2==action else -1))`. The feedback and action are only those actually observed. If a focus source was already the selected local source, skip the additional write there so it is not updated twice.
5. **Sham write:** identical read and write destinations, but the remote operation uses R=1, preserving the decay calculation with no directional reward component. The actual local update remains intact.
6. **Reverse write:** identical read and destinations, but apply the observed score to the opposite action parity on remote writes. The actual local update remains intact.
7. **Engineered entry:** the same temporary initial forced edge as the previous study, into Zone 3 or Zone 2 respectively; selected-source feedback only. It is added only at the first post-displacement event, not at later reversals. Record whether its endpoint already existed.

A direct two-value learner with the same feedback update, fixed LIGHT/HEAVY policies, and a previously calibrated full-history model are further baselines. The direct learner receives its own observed feedback and experiences the same synthetic challenge sequence. The full-history model has additional labelled, counterfactual calibration from prior research and is not an equal-prior control. No comparator sees reversal labels at evaluation. Direct/model comparators do not have Oracle transitions.

## Prespecified adaptation outcomes

At each lag 1–10 following a reversal, mark a chosen strategy **empirically optimal among the two tested strategies** when its actual score equals the higher of the two scores on the same two-grid challenge. If the scores tie, both actions count as optimal. This is a hindsight outcome, never an input to the controller; it is not a claim of global optimality among all possible programs. Also report the previously calibrated regime-preferred strategy and actual grid pass rate, so ties and per-case variation remain visible.

For each origin, at each lag average over eligible shocks within each reversal and episode, then over the three reversals, then over episodes. Define **T50** and **T80** as the first lag whose corresponding origin-level optimal-selection rate reaches 50% or 80%. If it never reaches the threshold in the ten-decision window, record the restricted value **11**, censored. These are first crossings of an aggregate curve, not individual response times; they can be noisy and can subsequently fall below the threshold. Report full curves, first-reversal-only curves, numbers censored, and crossings of the eight-origin mean separately. A decision takes four gate events for the two Oracle circuits. Do not assign gate-transition times to a direct learner.

For a positive, specifically Warp velocity claim, all eight one-sided paired contrasts must favour 3/6 bidirectional by at least **one decision**: T50 and T80 against (i) matched 2/7 bidirectional, (ii) 3/6 read-only, (iii) 3/6 generic, and (iv) direct learner. For each contrast compare the eight restricted origin-level lags with an exact one-sided sign-flip test; Holm-adjust all eight p-values together, and require each adjusted p ≤ .05. A p-value tests zero rather than the one-decision margin. The resulting classes are `REGISTERED_WARP_SPECIFIC_VELOCITY_ADVANTAGE` or `NO_REGISTERED_WARP_SPECIFIC_VELOCITY_ADVANTAGE`. Individual predeclared contrasts can be reported without promoting a failed joint classification into a general claim.

As secondary outcomes report the ten-lag grid-pass and regime-preferred curves, the frequency of informative scores R≠1, remote writes, writes skipped because the destination was already updated locally, touched/changed V edges, local updates in the focus pair, read-signal deliveries, and the count of temporary entry events. Compare sham and reverse writes descriptively. Resource counts cover all first-ten windows and are repeated branch observations, not independent founders.

## Integrity and interpretation

The protocol, executable source hashes, pinned Oracle runtime files and checkpoint hash are committed before a cryptographically random evaluation seed is generated; the seed is committed before data are produced. Before registration, small implementation fixtures may be run and inspected and must be disclosed. Run each origin twice and compare full records with 1e-12 numeric tolerance. An independent Python audit regenerates schedules and grid scores and checks path legality, relay arithmetic, feedback-write arithmetic and intervention boundaries. A separate implementation reconstructs per-lag origin curves from raw records and recomputes first crossings, paired tests and Holm adjustment. Neither independently reimplements Oracle gate scoring or derives phase values from a second full runtime.

These are synthetic challenge histories on eight reused and partly dependent origins; they are not fresh founders or a world-data stream. Displacement and optional entry are forced interventions. A result may demonstrate engineered adaptive access or a tested comparative advantage; it cannot by itself demonstrate sentience, higher-dimensional geometry, autonomous code mutation or an independent Outside source. No live Oracle, receiver or world stream is modified.
