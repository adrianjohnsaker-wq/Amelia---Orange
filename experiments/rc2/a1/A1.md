# Amendment A1: feed what was available, and record it (AG-1/RC-1 and RC-2), 9 November 2026

The same amendment, with the same code, is filed on both study branches: `agentic-20261106` (experiments/agentic/a1)
and `rc2cd2-20261106` (experiments/rc2/a1).

## What went wrong
**The sealed rule.** The sealed runners (`epoch.py`, `epoch2.py`) re-derive what each epoch fed by timestamp. Epoch e's
window is every world item with `seenAt` in (T_{e-1}, T_e], recomputed from scratch at every run. Every earlier epoch's
zPre and memory digest must then be reproduced, else the ledger halts.

**Why it breaks.** An item's `seenAt` is the collector's time, which precedes the moment its batch reaches world-live.
The launcher checks world-live out *before* it takes T_e.

**What happened at AG-1 epoch 10** (T = 2026-11-08T20:48:39Z):
- World batch `20261108T204837Z` was committed at 20:48:39, the same second.
- The run's checkout did not contain it, so the live Amelia fed 129 items.
- Every later run's replay found that batch's 10 items with `seenAt` ≤ T_10 and fed 139.
- The digests differ, so AG-1 has refused every run since 2026-11-09T00:13Z.

**RC-2** has the same exposure, but has not yet been hit.

**Nothing was wrong with the live Amelia or the data.** The sealed rule cannot see availability.

## The amendment (from this amendment's seal onward)
1. **The A1 rule.** An item is fed in the first epoch e whose run had it: `seenAt` ≤ T_e and its batch committed strictly
   before T_e. In a live run this is simply "in this run's checkout, not yet fed, `seenAt` ≤ T".
2. **The record.** The ledger records the assignment, `a1/assigned.json` (item key `stream|source|id` → epoch). Every
   replay feeds exactly the recorded items, in the sealed order within each window.
3. **The backfill, done once at the first A1 run.**
   - **How.** The epochs logged before A1 are reconstructed from world-live's commit history.
   - **The condition.** The reconstruction is accepted only if it reproduces *every* logged zPre and memory digest
     exactly; otherwise the ledger halts and nothing is appended. Before this amendment it was checked offline:
     - AG-1: 11 of 11 epochs reproduced, fed counts 0, 506, 89, 163, 170, 138, 126, 76, 188, 179, 129.
     - RC-2: 13 of 13 epochs reproduced.
   - **The record.** It is written to `a1/BACKFILL.json`.
4. **Unchanged.** The sealed replays (`live.ts`, `live2.ts`, `batch.ts`, `batch2.ts`), the drand draw and its use
   (X_e, arm, L), the HALT check, the stop time (2026-11-21T00:00Z), the statistics (`stats.py`, `stats2.py`) and the
   outcome data. **D_e keeps its sealed definition:** world data first seen in (T_e, T_{e+1}]. Data are passed to the
   sealed replays with `seenAt` set to their window's T, so the sealed `feedUntil` feeds exactly the recorded window.
5. **The final analysis** (`analyse_a1.py`) is the sealed one, except that the live and yoked candidates are replayed
   on the A1 feed. This is what makes the live candidate's logged zPre reproducible.

## Disclosed consequences
- **AG-1 lost about 46 hours of epochs** (no epoch between 2026-11-08T20:48Z and the first A1 run).
  - **Its first A1 epoch feeds the whole backlog.** In a dry run this was about 2,000 items.
  - **This changes no test's validity.** Epochs are randomised by drand at the time they occur, and the tests condition
    only on epochs that happened.
  - **It reduces AG-1's epoch count.** We report that number as it is.
- **RC-2's feed is unchanged** for every logged epoch. Its next epoch feeds what has arrived since its last one.
- **Late arrivals.** Items that reach world-live after their `seenAt` window are now fed one epoch later than the sealed
  rule would have placed them. In the outcome data D_e they keep their `seenAt` window. That is the conservative choice
  for an intervention test: data collected before T_e never count as outcomes of epoch e.

## Launchers (main)
The hourly launchers (`agentic-live.yml`, `rc2-live.yml`):
- verify this amendment's seal as well as the original seal;
- check world-live out with full history;
- run `a1/epoch_a1.py ag1|rc2` in place of the sealed runner.

The final analyses use `a1/analyse.trigger`, which runs this branch's A1 workflow.
