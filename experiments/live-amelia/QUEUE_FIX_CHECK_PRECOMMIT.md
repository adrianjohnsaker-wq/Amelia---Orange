# Queue-fix follow-up: registration before execution

The original pilot's corrected decision trace showed that rapidly generated field observations could fill the shared deferral queue while the Governor withheld admission. The application was then changed to retain only the newest *pending* field observation while leaving every Governor decision in PFM and preserving other encounter channels. Governor thresholds and admission decisions are not bypassed. The held-out application behavior is covered by a separate unit test with 50 forced deferrals, a non-field encounter, checkpoint restoration and subsequent Governor recovery.

This follow-up repeats the **same** eight seeds, 30-step acclimation, 50-step paired perturbation, live/shuffled/uniform mappings, halfway checkpoint and measurements specified in `PILOT_PRECOMMIT.md`, using the queue-fixed application source and `pilot.ts` committed together with this registration. Run `AMELIA_PILOT_PREFIX=queue-fix node --import tsx experiments/live-amelia/pilot.ts`. Store the `queue-fix-*` outputs and their hashes without replacing either earlier run. The runner refuses to overwrite existing output files.

Compare the per-offer Governor decisions, queue-full refusals and descriptive field recovery against the original pilot. This is an engineering follow-up to a problem found in that pilot, using the same seeds. It is neither independent replication nor a confirmatory test of an external mind, and any apparent changes combine the queue change with subsequent feedback dynamics. The user's continuing tablet history is not included.
